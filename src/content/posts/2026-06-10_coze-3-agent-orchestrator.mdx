## 从工具平台到操作系统

2025 年 4 月，Coze 2.5 发布时，它的定位从「零代码做 Bot 的平台」升级为「Agent 原生操作系统」。一年后，Coze 3.0 把这个定位做实了。

3.0 不是小修小补，是底层架构的重新设计。最核心的变化是：**从单 Agent 对话升级为多 Agent 协作系统。**

## 多人多 Agent 协作

之前 Coze 上搭 Bot 是一个 Bot 对应一个 Agent，用户和 Agent 一对一对话。3.0 支持两种新模式：

**一人 + 多 Agent** — 你下任务，系统自动拆解分配给多个专业 Agent 协同完成。比如写一篇行业报告 → 搜索 Agent 找素材 + 分析 Agent 处理数据 + 写作 Agent 成稿。

**多人 + 多 Agent** — 团队协作模式下，多人共享 Agent 资源池。项目独立管理，资产自动沉淀，不会把个人 bot 和团队 bot 混在一起。

这对企业场景很关键。之前的 Agent 平台本质上是「单人工具箱」，3.0 第一次做到了「团队工位」。

## 开放：第三方 Agent 接入

3.0 最大的差异化动作是开放了第三方 Agent 接入能力。

目前支持接入 Claude Code、Codex CLI、OpenClaw 等本地 Agent。这意味着你可以在 Coze 的工作流里直接调用 Claude Code 做代码审查、调 Codex CLI 跑自动化脚本、让 OpenClaw 处理文件操作——**所有 Agent 在一个平台编排**。

这在行业内是独一份。扣子不做排他，反而把自己做成 Agent 的「调度中心」。

## 行业模板：垂直场景全覆盖

3.0 内置了精品行业模板，覆盖自媒体、法律、金融、互联网、医疗健康等场景的专家 Agent。

以自媒体场景为例：预设了选题挖掘 Agent、素材收集 Agent、初稿 Agent、排版 Agent、发布 Agent。你只需要定义选题方向，剩下的全自动跑。

这些模板不是简单的提示词预设，而是**完整的工作流编排**，附带知识库和工具配置。对非技术用户来说，开箱即用的门槛低了很多。

## Coze 3.0 的战略逻辑

从字节跳动的视角看，Coze 3.0 的战略意图很清晰：

**定位从 Builder 到 Orchestrator。** 你不是在扣子里「造」一个 Agent，而是在扣子里「管」一群 Agent——包括不属于扣子的 Agent。扣子变成了 Agent 生态的编排层。

**生态绑定。** 第三方 Agent 接入得越多，开发者对扣子的依赖就越深。一旦你的工作流里跑着 Claude Code、Codex CLI、OpenClaw 多个 Agent，迁移成本就不是重写一个工作流那么简单了。

**商业化路径清晰。** 多 Agent 协作 = 多 Token 消耗 = 更高的平台使用深度。2C 免费拉量，2B 按编排复杂度收费，是字节的惯用打法。

## 和竞品的区别

对比同期的其他 Agent 平台：

- **百度秒哒** 走的是封闭生态，只接自家模型和工具
- **Coze 3.0** 走开放路线，任何 Agent 都能接入
- **Manus** 走全托管路线，用户只管下任务

三个方向各有优劣。Coze 的开放策略在「存量 Agent 管理」场景下有天然优势——如果你的团队已经在用 Claude Code 了，Coze 能直接编排它，而 Manus 做不到。

## 写在最后

Coze 3.0 值得关注的不只是新功能，而是它定义了一类新品类：**Agent Orchestrator**。不是造 Agent 的平台，是管 Agent 的平台。

当 AI 工具多到管不过来的时候，谁来做调度层就成了新问题。字节在这块抢了个先手。
